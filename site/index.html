sidediff

See what changed between two live sites.

Point it at an old site and its replacement. It finds the paths itself, screenshots both sides, diffs the text as well as the pixels, and hands you one report showing exactly what moved, broke, or disappeared.

Not baseline-vs-rerun visual regression. Both sides are live URLs — the shape a migration or redesign audit actually has, and the shape the dormant tools in this space stopped serving.

Rows sort worst-first. Click any one for a slider, side-by-side, the raw pixel diff, or the text diff. Redirect targets are recorded per side — redirect parity is half the value of a migration audit.

Text diffs too, not just pixels

Every page's rendered text is diffed GitHub-style, alongside a table of title, description, canonical, og:*, and the heading and link inventories. This is the check that catches a nav item or a whole section quietly missing on the new site — the thing pixel percentages are worst at.

Rendered text, not markup — class hashes and build ids churn every deploy, so a raw HTML diff reports everything as changed on a visually identical page. It is also immune to the height mismatches that make pixel percentages hard to read.

Get started

# clone, then
bun install
bunx playwright install chromium

bun run compare --a https://old.example --b https://new.example

Report lands in sidediff-out/index.html. Exit code is 1 if anything changed or failed to load, so it drops into CI as-is.

How it works

Finds the paths

Unions sitemap.xml (following sitemap indexes and robots.txt) with a link crawl, so a stale or partial sitemap doesn't decide your coverage.

Collapses templates twice

By shape, and by sibling count — a parent with many children at one depth is a listing, whatever its URLs look like. A flat limit fills breadth-first with near-identical doc pages and never samples the rest of the site.

Pins everything that renders nondeterministically

Animations off, sticky made static, Date and Math.random frozen, locale and timezone fixed, analytics blocked, consent banners hidden, fonts awaited, lazy content scrolled into existence.

Diffs, then tells the truth about it

Size mismatches are labelled separately from pixel changes, text-only changes get their own bucket, and a page counts as unchanged only if it clears both a percentage and an absolute pixel floor.

Why those last two matter

Taller ≠ changed

odiff counts the entire non-overlapping region as different. A page that is merely 400px longer would read as a huge diff, so those rows get their own bucket and tolerance never applies to them.

Percentages lie on long pages

On a 20 000px page, 0.05% is ~100k pixels — enough to swallow a swapped logo. A change must clear a percentage and ~20k pixels to count as unchanged.

Fixed elements stay visible

Modern Chromium renders them once in a full-page shot. Fixed navs and CTAs are exactly what a redesign changes, so hiding them by default would blind the diff. --hide-fixed opts out.

One-sided paths are a finding

A URL that 200s on A and 404s on B is reported, not silently dropped into a garbage comparison. Same for redirects that only happen on one side.

Flags worth knowing

--paths-file
Skip discovery entirely and supply the list yourself. The crawler reads server-rendered HTML only, so SPAs and bot-protected sites want this.
--viewports
Any set of name:WIDTHxHEIGHT. Defaults to desktop and mobile.
--hide / --mask
Selectors to remove, or paint over, before diffing. For carousels, chat widgets, anything you know will never match.
--tolerance
Diff percentage below which a page counts as unchanged. Pairs with the built-in absolute pixel floor.
--limit / --per-template
Volume caps. Coverage is handled by template collapse, not by these.
--no-text
Skip the rendered-text and meta-tag diff and compare pixels only.
--freeze-time
Pins the clock so client-rendered timestamps stop diffing. none disables.
